# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Raycast extension that generates dummy My Numbers (Japanese Individual Numbers) with a valid check digit. Published to the Raycast Store via a PR to `raycast/extensions` (the store copy lives in that monorepo; this repo is the development home).

## Toolchain and Commands

The toolchain (bun / node) is managed with mise (`mise.toml`). Node is required because the `ray` CLI runs on it. Run tools through `mise exec --` if bun/node are not already on PATH.

```sh
mise install        # install bun / node
bun install
bun run dev         # import into Raycast in development mode
bun test src        # run tests (bun test runner)
bun run lint        # oxlint
bun run fmt         # oxfmt (fmt:check for CI-style check)
bun run knip        # unused dependencies/exports
bun run build       # ray build -e dist -o dist (includes TypeScript check)
bun run publish     # regenerate package-lock.json, then submit to raycast/extensions
```

There is no separate typecheck script; `bun run build` performs type checking. A single test file exists (`src/mynumber.test.ts`); to run one test use `bun test src -t "<test name>"`.

## Architecture

Two-file split in `src/`:

- `mynumber.ts` — pure check-digit logic (Ordinance No. 85 formula: `11 − ((Σ Pn × Qn) mod 11)`, 0 when remainder ≤ 1). Unit-tested with hand-calculated examples; imports in tests use the explicit `.ts` extension because tests run on bun/node type-stripping, not the ray bundler.
- `generate-mynumber.ts` — the single no-view command. Uses the auto-generated global types from `raycast-env.d.ts` (`Preferences`, `Arguments.GenerateMynumber`); do NOT hand-write a `Preferences` interface — that was rejected in store review. `raycast-env.d.ts` is generated by `ray build`/`ray develop` and is gitignored.

Command metadata (title, arguments, preferences) lives in `package.json` (the Raycast manifest). After changing preferences or arguments, run `bun run build` to regenerate the types.

## Conventions

- Commit messages and PR descriptions in English (public repo; overrides the global Japanese-commit rule).
- "Mynumber" is intentionally one word (proper noun for マイナンバー), not "My Number". Keep this in all user-facing strings.
- Two lockfiles are committed on purpose: `bun.lock` (used by CI) and `package-lock.json` (required by the Raycast Store publish validation). The `publish` script regenerates `package-lock.json` automatically.
- GitHub Actions in workflows are pinned to commit SHAs with pinact (`pinact run -u` to update).

## Releases

tagpr automates releases: every push to main creates/updates a release PR (bumps `version` in `package.json`); merging it tags `vX.Y.Z`, which triggers `.github/workflows/release.yml` to build and attach a zip to a GitHub Release. tagpr authenticates with a GitHub App (repo variable `TAGPR_APP_ID`, secret `TAGPR_PRIVATE_KEY`); tagpr's own changelog generation is disabled (`.tagpr`) because `CHANGELOG.md` follows the Raycast Store format (`## [Title] - {PR_MERGE_DATE}`).

## Store Submission Notes

- Store PR: https://github.com/raycast/extensions/pull/29894. Re-running `bun run publish` updates the same PR.
- `metadata/` screenshots must be 2000x1250 PNG, and the store CI validates content padding: 8–17% on every edge, top/bottom and left/right roughly symmetric (diff ≤ 4%). Wide or square captures (HUDs, settings windows) cannot pass. The validator detects the window by luminance gradients, so drop shadows do NOT count as content — position based on the detected window edges, not the alpha bounding box (see `scratchpad`-style two-pass compositing in the git history of `metadata/`). Validate locally with `bun run check:metadata` (`scripts/check_raycast_images.py` is vendored from raycast/extensions; requires Python with numpy and Pillow).
- `ray publish` copies files to the store PR branch but never deletes removed ones; delete stale files on the fork branch (`upamune/raycast-extensions`, branch `ext/mynumber-generator`) via the GitHub contents API.
- `author` in package.json is the Raycast account handle (`serizawa`), not the GitHub username.
